About me

I'm a cybersecurity professional based in Kenya. I started as a backend engineer building Node.js and REST APIs, so I understand how systems are built, and that helps me defend them.

In my current role I secure live infrastructure, run Wazuh as our SIEM, evaluate vulnerability and audit tools, and lead a Data Protection Impact Assessment (DPIA) programme for compliance with Kenya's Data Protection Act 2019. I build security frameworks on ISO/IEC 27001 and 27002, and I am writing our first incident response playbook. I also design business processes, build enterprise applications and teach people to stay safe online.

I can investigate an alert in the SIEM, then explain to leadership what it means for risk, compliance and the people whose data we protect. I have just passed Microsoft SC-200 and am growing toward SOC analyst and cloud security roles.

Lab challenges

Building a working SIEM with alerting
Problem
Monitor mixed systems, get email alerts for real events and know which vulnerabilities to fix first.
Approach
Installed Wazuh, enrolled agents (including the SIEM host itself), set up Postfix with Gmail for alerts and tracked each CVE from detection to resolution, checking whether newer patches superseded older ones.
Tools
Wazuh, Ubuntu on WSL, Postfix, Windows Server
Lessons learned
Alert tuning matters as much as collection, and patch supersedence can close several findings at once.
SOC home lab
Problem
Practise attack and detection safely without touching production systems.
Approach
Built an isolated virtual network with an attacker machine and a Security Onion sensor, and worked through installation, networking and disk space limits.
Tools
VirtualBox, Kali Linux, Security Onion 2
Lessons learned
Plan resources and network segments before installing, and document each build so it can be repeated.
